# Decisions Log

Ambiguities resolved while building, simplest-option-first, to keep the demo reliable.

- **Prisma schema location**: kept at root `/prisma/schema.prisma` (per monorepo layout in the spec) rather than inside `apps/api`, so both the API and the seed script share one generated client via workspace hoisting.
- **DB file location**: `prisma/dev.db` (SQLite), referenced via a relative `DATABASE_URL` so it works the same on any machine after `git clone`.
- **ML venv bootstrap**: `postinstall` runs `npm run ml:setup`, which creates `apps/ml/.venv`, installs `requirements.txt`, and runs `train.py` to produce the pickles — so `npm install` alone is enough, no separate ML setup step for the presenter to remember.
- **Project name / branding**: named after the team from the SIH slide deck ("DoomCore") in README/UI footer only — no functional impact.
- **Cross-platform npm scripts**: `cmd.exe` (npm's default script shell on Windows) refuses to resolve a forward-slash executable path (`.venv/Scripts/python`) — it needs backslashes. Rather than hand-write OS-specific script strings, `ml:setup`/`ml:dev` shell out to small Node scripts (`scripts/ml-setup.js`, `scripts/ml-dev.js`) that pick the right venv layout (`Scripts/` vs `bin/`) via `process.platform`.
- **Local-date consistency bug (fixed during build)**: several places computed "today" as `new Date().toISOString().slice(0,10)` or (worse) `local-midnight.toISOString().slice(0,10)`. Both convert to UTC first, which silently shifts the calendar date by one day in any timezone ahead of UTC (e.g. IST) — this was caught when seeded "today" bookings landed under yesterday's date. Fixed with one shared `localDateStr()` helper (`packages/shared/src/date.ts`, local getters only, no UTC conversion) used everywhere a calendar day is derived from "now" (seed, cron, staff/admin "today" queries, voice date parsing). `apps/web` inlines its own copy rather than importing the runtime value from `@msp/shared` — see next point.
- **`@msp/shared` runtime imports from the web app**: Rollup's CJS-interop analysis of the shared package's compiled `dist/index.js` (a chain of `__exportStar(require(...))` barrels) failed to statically detect a genuine runtime export (`localDateStr`) during `vite build`, even though it resolves fine under plain Node `require`. Type-only imports (`import type { ... }`) are unaffected since they're erased before bundling. Rather than fight Rollup's CJS export detection, `apps/web` only ever does `import type` from `@msp/shared` and inlines the one small runtime helper it needs.
- **`EventLog` table**: kept in the Prisma schema per the spec's data model, but left unused — admin analytics reads directly from `Booking` (grouped by its `slot.date`), which is simpler than also maintaining a parallel event stream and produces the same charts for this demo's scope.
- **Demo reset via subprocess**: `POST /api/demo/reset` shells out to `npm run seed -w apps/api` (scoped to the API workspace, not the root `seed` script, so it skips rebuilding `packages/shared` every time) rather than importing `prisma/seed.ts` directly — that file lives outside `apps/api`'s TypeScript `rootDir`, so a direct import breaks `tsc` builds. Measured at ~1.1s end-to-end, comfortably under the 2s budget.
